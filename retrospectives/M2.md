# M2 retrospective

`M2` built the three outer libraries and the evidence checker, each standalone, on the runtime and format `M1`
adopted: the state machine library and its VOS program (`F-010`), the router (`F-011`), the catalogue and grants
(`F-012`), module admission, runtime and lifecycle (`F-013`), the shared credential proxy (`F-014`), the evidence
checker (`F-015`) and the holding-account modules (`F-016`). This page says what worked, what didn't, and which
lessons should change the method. Facts come from the commits on `m2` (`447fb0f` when this page was written), the
feature notes under `features/`, the contracts' changelogs and `PLAN.md`.

## What worked

- **A fresh reviewer for every task caught blockers the author did not.** The notes record the ones that mattered:
  - **A credential followed a redirect.** A `302` from one endpoint to another carried the first's `Authorization`;
    the second round found the drop went by a flag, so a plain `Authorization` still followed (`T-014-03`).
  - **The signer signed what it was not asked.** A statement nested in a provider's result was signed whatever
    operation it answered; the signer now signs only a judgement or a reversal confirmation that answers the
    operation handed out (`T-014-05`).
  - **A slow peer outlived the deadline.** Each read had its own timeout and nothing bounded the exchange, so a
    peer sending a byte now and then held the platform, and every other provider, for 20 s against a 2 s deadline
    (`T-014-05`).
  - **The wallet's balance was the host's own sum.** `reconcile` could never return `Short`, so a wallet that lost
    its record still looked whole. The contract had no balance shape, so `holding_balance` was added (`T-016-02`).
  - **A refused request left no record.** A request the platform would not send was refused though the call was
    charged and `REQ-MDL-8` wants every call recorded; `request_not_allowed` joined module-interface (`T-013-07`).
  - **A statement's context went unchecked** (`T-012-02`), as did a nested one (carried to admission, `T-013-04`).
- **Fix now, because nothing is in production.** The owner's rule: a contract gap found in `M2` is fixed in `M2`,
  not deferred. It paid off each time: the wallet's balance, the missing refusal reasons (`T-010-09`), the drop
  reasons (`T-011-05`), the route's named calls (`T-011-06`) and the WIT's missing shapes (`T-013-07`) all landed
  before any caller depended on the gap.
- **Unreleased majors absorbed further changes.** `develop` holds 2.x, so `holding_balance` and `request_not_allowed`
  folded into the 4.0.0 and 3.0.0 already pending on `m2`. Consumers see one bump per contract at the release, not
  one per fix.
- **Each test seen failing first, by mutation where the code came first.** The notes say which were shown red, and
  how (a rule switched off, then restored unchanged). Reviewers could trust the tests that carry the `DEC-20` paths.
- **Rows added when a review found unowned work.** `T-010-09`, `T-010-10`, `T-011-05`, `T-011-06`, `T-013-07`,
  `T-014-05`, `T-016-04` each began as a review finding or a note's "item", and each got an owner, a test list and a
  done-when, so nothing sat in prose.
- **Scoring in CI.** The platform-specific runs (VOS on Linux x86_64, the re-derivation on two CPU vendors) went
  through GitHub's runners, so each scored number names a run.

## What didn't

- **The machine crashed under parallel builds.** Too many agents building at once exhausted the 16 GB of memory.
- **The disk filled** and stalled every agent, as it had in `M1`.
- **An agent's `pkill` by pattern killed other sessions' builds.** The pattern matched processes that were not the
  agent's own.
- **CI on `m2` sat red unnoticed for four integrations.** The cause was the documentation check, a different check
  from the tests each task ran locally.
- **GitHub's API rate limit was exhausted by polling** run status too often.
- **The contract guard compared a milestone push with the previous commit.** Each integration looked like a small
  change, so a bump held for the whole milestone was never judged against `develop`. It was changed to compare
  with `develop` (`28f16cc`).
- **Tests were written alongside the code in several tasks** rather than first. `T-012-02`'s notes say so: the
  verifier was written before its tests, which were then shown able to fail by disabling each rule. `T-013-07`'s
  guests and world were written together, so its tests were shown red by mutation. The result is sound; the order
  broke the brief.
- **Reviews kept adding rounds to a few tasks** (`T-014-03`, `T-014-05`, `T-013-07` each had a second look), partly
  because a fix opened the next gap. Most were closed by an exit rule in the brief, as `M1` taught.
- **Wrong probe, read as a verdict.** The userfaultfd probe's own struct-size bug failed two CI runs and read as
  "the host does not allow it" (`T-010-08`). The probe now exits 2 on its own failure.

## Lessons that change the method

These go to the methodology store as proposals (Narthex `REQ-CHN-18`, `XC-4`). None changes rutent's plan.

1. **A memory budget for parallel builds.** A brief says how many builds may run at once for the machine's memory
   (here 16 GB), sets `CARGO_BUILD_JOBS` and a task-specific `CARGO_TARGET_DIR`, and the lead counts agents against
   that budget, not only against the plan.
2. **Brief rules for every agent.** No `pkill` or `killall` by pattern: stop only a process you started, by its own
   id. Poll CI at `--interval 60` or slower. The documentation check is in every
   brief's list of checks to run before a task is called done.
3. **Watch CI after every push to a milestone branch,** and treat a red run as the lead's next task, not the
   task's. A check that can fail on a push is part of "integrated".
4. **The contract guard compares a milestone push with `develop`,** since a milestone's contracts are unreleased
   majors that must be judged against what shipped.
5. **Add a plan row mid-milestone when a review finds unowned work.** Name the task, its tests and its done-when
   at once, so the finding is built and checked, not noted.
6. **Tests first, and say when they were not.** The notes record the order. Where code came first, the brief
   requires each rule to be switched off in turn and its test seen red, as `T-012-02` did.
7. **Fix a contract gap in the milestone that finds it** while nothing is in production, and fold it into the
   unreleased major rather than opening another.

## What `M3` inherits

Core (`F-020` to `F-025`) binds the libraries. The notes hand it, among others:

- **`Platform::routes` filled from live orders.** `T-011-06` makes the router name each segment's calls and
  `T-014-04` refuses any call the route does not name, but only Core knows the live segment, so it fills the
  platform's `RouteCalls` when it hands a segment's operation over (`T-014-04`, `T-014-05`).
- **`quote_voided`.** Unowned. Core asks again at a shifted amount and cites the voided quote; the contract allows it
  and the router keeps `stale_figure` for the validity case (`F-011`, `T-011-04`).
- **Drop-reason and contract items.** The inputs router-api does not carry, left open for Core's contract task: the
  operator's fee formula, the slippage limits, the history of stated terms, the actual settlement times and the held
  quote, and whether ranking should be net of the operator's fee. How Core reaches the `quote` module's types under
  `DEC-2` is open too. A reason for a malformed request that is aimed at an undeclared host stays
  `request_not_allowed`, read as "refused before any destination was judged" (`T-013-07`).
- **One amount per tuple (`cat5-single-amount-asks`).** Other paths' operations at that tuple stay `unconfirmed` in
  a choice round until Core asks at their amounts. Keeping the questions unlinkable is Core's, or accepted residual
  risk (`F-020`).
- **Staging defaults.** `Lifecycle::default()` holds a 10 % share, a one-day window and a minimum of 100 operations;
  they are `T-013-06`'s reading. The deployment's settings own them (`M4`), and `set_staging(None)` puts an upgrade
  in force at once, which the test platforms use.
- **The cold store** for what the journal archives, with the rest of `G-33`: `T-010-07` and `vos-storage-bound`
  decide its shape.
- **Core's guards named in `F-012`:** the clock Core passes as `at`, the session register, the `own_order` check,
  and delivery to the operator (`F-022`).
- **Hand-offs to later features:** simulated providers that carry state across operations (`F-024`), the
  wasmtime advisory about x86-64 AVX code that the explicit baseline target does not emit (`F-025`), the cgroup that bounds what a provider may use and the operator's rate
  over time (`F-030`), the operator's runner obligation (`F-030`, `F-033`), and each network's finality rules
  (`F-031`).
- **Found by the review of the milestone's pull request (`M2` handing to `M3`).** One line each, with the row that
  will own it on branch `m3`:
  - **The hand-on rule admits more than one second order** (`components/stm/src/hand_on.rs:23-31`). Before the first
    order's `handed_on`, every waiting or stuck part holds value for any order that names it. Core calls it only
    after `handed_on`, or the rule requires `HandedOn` with `linked_order == second`; add the two-orders test
    (`INV-4`). `T-020-13` (the start rule, called with both orders), checked again by `T-024-08`.
  - **A handed-on start says the holding account's withdrawal settles the route's first segment**
    (`components/prov/src/holding/wallet/handed_on.rs:37-46`, `:120-159`), but the test's first segment is a
    `route` operation of another provider, and the state-machine README says a route handed on has no withdrawal
    segment. Decide the reading, then make the doc, the test and the contract agree. `T-020-13` (the holding
    account's record proving the handed-on route's withdrawal, `REQ-ORD-40`).
  - **The customer's floor is judged before the operator's fee** (`components/router/src/judge.rs:113-116`; the
    fee comes after: the router's doc, `lib.rs:52-54`, and the fee itself in `quote.rs:218-238`). Compare after the fee, or say it in the contract and re-check it in Core
    (`REQ-ORD-27`, `AC-12`). `T-020-07` (the fee shown apart), with `T-020-02` for the fee formula and `T-020-10`
    for the floor on recalculation.
  - **The plain wallet's record lives only in its instance** (`components/prov/guests/plain-wallet/src/lib.rs:41-47`).
    After a provider restart, which a staged release can cause, `held` is empty, so `release` and `start_handed_on`
    fail and a stuck order can't be handed on (`REQ-ORD-43`); `reconcile` does detect it (`F-016`'s notes).
    `T-020-13` is the nearest row (the hand-on); no `m3` row owns persisting the wallet's state, so it needs one.
  - **Duplicate-transaction protection is opt-in** (`components/prov/src/module/lifecycle.rs:494-501` (`begin_segment`) and `:539-553`): an
    operation with no `begin_segment` runs with no duplicate check, so the test tagged `INV-8` covers less than its
    tag. Make Core's `begin_segment` mandatory or refuse unsegmented transactions. `T-020-08` (Core begins and ends
    every segment).
  - **Lifecycle permissions** (`components/prov/src/module/platform.rs:1761`, `:2020-2088`): any caller can mark
    stale, revoke, declare exploited, accept or promote (`REQ-MDL-5`, `REQ-AUZ-6`). `T-021-03` (granting,
    accepting, revoking, marking stale and declaring exploited as separate permissions, `REQ-AUZ-6`); its row does
    not name promotion of a staged release, which should be added to it. (On `m2`'s `PLAN.md` no row cites
    `REQ-AUZ-6`; `m3`'s `T-021-03` does.)
  - **Staged-release promotion counts refusals as observations** (`components/prov/src/module/lifecycle.rs:138`,
    `:657`), so a release that traps on its whole share can be promoted. Gate on answered operations or a refusal
    rate, or say in ADR-0014 that the judgement is the operator's alone. No `m3` row owns it; the nearest is
    `T-021-03` (who may promote), and `T-013-06`'s lifecycle is `M2`'s, so a row is needed.
- **Name resolution** by the operating system is not bounded by the operation's deadline (`getaddrinfo` takes no
  timeout); noted, not changed (`T-014-05`).
