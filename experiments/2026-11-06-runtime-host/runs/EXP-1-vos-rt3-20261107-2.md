## How each fault was reached

| Fault | How |
|---|---|
| Kill and reopen | `kill -9` of every node's process, then each started again on its own data directory |
| Stop after received | The input held by the client, nothing sent; every node killed |
| Stop after computed | Faults build: every node's faults file set to `hold_commits` and each node's `generation` seen; the submit sent; once the leader's `refine` stage counted it (the program computed), every node killed. Held, no node can have made it durable. On the scored build nothing is held: the same kill lands after the compute, unheld, which is not `H-02`, `H-06` or `H-11`'s test |
| Stop after durable | The program answered the submit as recorded, so it is committed; every node killed before the client returns |
| Stop during an import | Every node killed between two chunks' calls |
| Leader killed mid-submit (`R-01`) | `kill -9` of the leader alone, each node its own OS process |
| A replica lost or replaced (`R-02`, `R-03`) | VOS's `replace` at the leader, the new node's own key, its data never copied |
| The last batch damaged (`R-04`) | The node killed, the newest file of fjall's journal in its store cut by 8 bytes or its last byte flipped, the node started again |
