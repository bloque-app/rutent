## The design, as run

- **The platform is the suite's process.** `WasmBinding` (`binding/src/platform.rs`) implements `ModuleBinding` and
  `BoundaryHarness`. It holds the credential proxy, each provider's state, the egress layer and the simulated
  endpoints behind it, the cross-module router, admission and every artefact, and makes every check against the
  provider's **running** declaration.
- **One OS process per provider.** Each started release runs in a `rutent-wasm-provider` process of its own, with
  both parts' components in two separate Wasmtime stores. Every import either part calls is a request to the
  platform over the process's standard streams, in length-prefixed frames; the platform attributes it to the
  provider whose pipe it came on, never to anything it says (`DEC-9`). `process` is the child's OS pid, and
  `restart` kills that one process and starts the running version again from its admitted machine code. An upgrade
  starts in a new process and replaces the old one only once both parts have started; a release that doesn't start
  leaves the old process and version in force. A version already admitted, accepted or waiting, is not admitted
  again, and a waiting release's machine code is kept apart from the running version's until it is accepted
  (`tests/process.rs`). A process that dies is started again by the platform, as a
  supervisor would, at the operation that finds it gone.
- **Bound to the request in flight.** Every secret lookup, outbound call, state read and cross-module call is judged
  against the outside request the platform is serving, from its own state: a lookup or a call naming another
  operation is refused (`undeclared_secret`, `undeclared_operation`), and the outbound call record names the
  operation in flight, never the one the guest named (`tests/egress.rs`).
- **The admitting compiler in its own isolation.** Each admission starts a fresh `rutent-wasm-compiler` process,
  isolated as below, that reads both portable binaries on its standard input, refuses anything Wasmtime recognises as
  precompiled, compiles each part with `Component::new`, links it against the part's own interface only
  (`instantiate_pre` and the world's `*Pre::new`, which type-check imports and exports without running anything), and
  writes back `Component::serialize`'s bytes. Their SHA-256 is each part's `build.machine_code`. A provider's process
  checks both parts' digests against the artefact's before it loads or instantiates either, and only then calls
  `Component::deserialize` (`G-08`).
- **Isolation of every child** (`sandbox/src/lib.rs`), as run here on macOS: environment cleared, only the three
  standard streams inherited, an empty working directory of its own (one per child, removed when it ends), every file descriptor from 3
  up to the parent's open-file limit (at most 65,536) closed before `exec`, close-on-exec or not, standard error a
  pipe the platform reads and prints under the child's label, `RLIMIT_CORE`, `RLIMIT_FSIZE` and `RLIMIT_NPROC` at 0,
  `RLIMIT_NOFILE` bounded (16 for the compiler, 32 for a provider), `RLIMIT_CPU` 60 s for the compiler, `SIGXFSZ`
  ignored so that a write fails rather than kills, and a
  `sandbox-exec` profile that **denies by default**, denies `process-info*` and `iokit-get-properties` again
  explicitly, and allows only executing the child's own executable; reading it, `/` itself, `/usr/lib`, `/System`,
  `/dev/null`, `/dev/urandom` and `/dev/random`, and their metadata, nothing else's; `sysctl` reads; and signals to
  itself. The executable's path is escaped as a string of the profile language. On Linux the same code applies `no_new_privs`, a new user and
  network namespace where unprivileged ones are allowed, and a seccomp filter that refuses `socket(2)` and any
  signal to another process. **The Linux layer does not meet the deny-by-default bar**: the filter is a deny list,
  and nothing restricts file reads, so a child there can read `$HOME`. It was type-checked (`cargo clippy --target
  x86_64-unknown-linux-gnu` and `aarch64-unknown-linux-gnu`) but never run, and the probe test asserts the home-file
  read on every platform, so it fails on Linux until a file-read layer is built. Holes a Linux rebuild has to close,
  not verified here: x32 system-call numbers (`nr | 0x40000000`) pass the `socket(2)` match under the same
  `AUDIT_ARCH`; `io_uring_setup` can make sockets without `socket(2)`; `pidfd_send_signal` signals without `kill`.
- **The interface** (`wit/binding.wit`, item `exp2-wasm-shape`). The sandboxed part's world imports
  `rutent:binding/outside-requests@0.1.0`, its one route outward, which carries the contract's outside request and
  response as JSON, and `rutent:binding/denied@0.1.0`, which records an attempt at a secret or at state and returns
  nothing. An attempt names no operation: the platform records a secret attempt under the running declaration's
  first outside operation and the transaction being handled (item `exp2-wasm-sandboxed-surface`). The outside part's world imports `proxy`, `state`, `egress` (item
  `exp2-outside-egress`) and `modules`. Each exports `start` and one entry point.
- **The stand-ins.** One module per category (reserve, exchange, ramp, verifier) in each language, each part a
  component: sixteen components. Each carries the suite's `ModuleSpec` as a program in an 8,192-byte slot of its
  data segment, filled with `#`; `build` writes the spec's program into that slot in place, so every module the
  suite builds is a stand-in's own compiled code reading its own steps (item `exp2-wasm-standins`). The sandboxed
  part drives the steps, sends each outside step as an outside request carrying the values obtained so far, and
  renders the output; the outside part runs the step it is asked for. Each sandboxed part also answers its
  category's own kind (`deposit`, `conversion`, `transfer`, `judgement`) with a final refusal, a valid result of
  that kind.

## Gaps found

- **The role suite through the binding** (`B-01`): not run; the stand-ins carry the module-boundary suite's steps
  and one answer of their role's kind, not the role behaviour `T-002-03` probes.
- **Limits beyond CPU and linear memory** (`B-14`, `G-05`): none per module or provider for outbound calls, state or
  pending work, and nothing bounds a provider process's whole memory.
- **Output schema** (`B-19`): patterns and lengths aren't checked.
- **Spectre** (`G-09`): defaults, not a choice.
- **Linux isolation** does not meet the coordinator's deny-by-default bar: a deny list, with no file-read
  restriction and the holes listed above; untested; on Ubuntu 24.04 unprivileged user namespaces are restricted by
  AppArmor by default, and the network namespace would then not take. The probe test fails on Linux until it is
  rebuilt.
- **Fuzzing** (`B-09`): no fuzzer-made binary and no fuzz corpus was admitted.
- **The refusal for a guest stopped mid-operation** is `PlatformRefusal::Unavailable`: the suite's enum has no
  reason for a trap or a limit.
- **Signing** is the suite's placeholder, as in the suite (`M2`, `M3`); the platform, not the outside part, wraps
  the result in its envelope.
- **Routes**: a cross-module call's route is the suite's placeholder, and no route is checked; outside an outside
  request in flight, a declared call is refused as `not_named_by_route`.
- **The run platform**: the cells this run fills are development cells; the scored run on x86_64 Linux is still to
  be made, and `run.sh` has not yet been run there.
- **Re-admitting a version**: refused, as `UnreadableBinary`, since the suite's `AdmissionRefusal` has no reason for
  a version already admitted.

- **Inherited descriptors.** A descriptor the platform held open without close-on-exec reached the child, where
  the profile's file-read denial didn't stop reading it. Every descriptor from 3 up is now closed before `exec`, and
