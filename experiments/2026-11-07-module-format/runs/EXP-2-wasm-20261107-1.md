## The design, as run

As in [the development run's note](EXP-2-wasm-dev-20261107-2.md#the-design-as-run): the platform is the suite's
process; each started release runs in a provider process of its own, both parts in two Wasmtime stores, every import
a framed request to the platform over the process's standard streams; every lookup and call is judged against the
outside request in flight; each admission compiles in a fresh admitting-compiler process, whose output's SHA-256 is
each part's `build.machine_code`, checked by the provider's process before `Component::deserialize`. What differs on
Linux is the isolation of every child, and that a provider's process is two processes: `unshare`, whose process id
the platform holds, and its one child, which runs the module.

### Isolation of every child, on Linux (`sandbox/src/lib.rs`)

Each layer denies by default. In the order they apply, as the report's `isolation` lists them:

1. **Before `exec`** (`isolated`, `pre_exec`): environment cleared; every descriptor from 3 up closed with
   `close_range(3, ~0)`, close-on-exec or not, so only the three standard streams, each a pipe to the platform,
   remain; an empty working directory of its own; `RLIMIT_CORE` 0; `RLIMIT_FSIZE` 0 for the compiler and 16 MiB
   for a provider (below); `RLIMIT_NOFILE` 16 for the compiler, 32 for a provider; `RLIMIT_CPU` 60 s for the
   compiler; `SIGXFSZ` ignored, so an over-limit write fails rather than kills.
2. **Namespaces:** the child is started as `unshare --user --map-root-user --net --ipc --uts --mount --pid --fork
   --kill-child -- <executable>`, util-linux 2.39.3, found on the platform's `PATH`: new user (root mapped to the
   platform's user), network, IPC, UTS, mount and PID namespaces. The executable is PID 1 of its PID namespace and
   gets SIGKILL if `unshare` ends.
3. **The jail, in the child, before it reads any input** (`confine`, called first in `main` of both
   `rutent-wasm-compiler` and `rutent-wasm-provider`; any step that fails stops the child):
   - it refuses to go on unless it is PID 1 of its own PID namespace;
   - `prctl(PR_SET_NO_NEW_PRIVS)`;
   - every mount made private; a `tmpfs` mounted read-only, `nosuid`, `nodev` and `noexec` on `/tmp`; the root moved
     to it with `pivot_root(".", ".")` and the old root detached (`umount2(MNT_DETACH)`). The child's whole
     file-system view is that one empty, read-only directory: no home directory, no `/run`, no `/var/run`, no
     `/proc`, nothing of the machine's. It checks that `/home`, `/root`, `/run`, `/var/run`, `/proc`, `/usr` and
     `/etc` are gone, and stops if one is not;
   - `close_range(3, ~0)` again;
   - `RLIMIT_NPROC` 0, `RLIMIT_CORE` 0, and for the compiler `RLIMIT_AS` 8 GiB;
   - every capability dropped: the bounding set emptied, securebits set and locked (`SECBIT_NOROOT`,
     `SECBIT_NO_SETUID_FIXUP`, `SECBIT_KEEP_CAPS` locked off, `SECBIT_NO_CAP_AMBIENT_RAISE`), the ambient set
     cleared, the effective, permitted and inheritable sets emptied with `capset` and checked empty with `capget`;
   - **Landlock**, which the runner's kernel has (`LSMs: lockdown,capability,landlock,yama,apparmor,ima,evm`): a
     ruleset of the kernel's ABI, **8** on this kernel, as both children's probe reports give it, that handles
     every file-system right up to `IOCTL_DEV`, TCP bind and connect, and scopes abstract Unix sockets and
     signals to the domain, with no rule, so every one of them is denied;
   - **seccomp**, last: an allow-list. A system call from any architecture but x86_64 (`AUDIT_ARCH_X86_64`), or of
     the x32 ABI (`nr >= 0x40000000`), kills the process. Allowed, for both children: `read`, `write`, `readv`,
     `writev`, `close`, `fstat`, `newfstatat`, `statx`, `lseek`, `fcntl`, `mmap`, `mprotect`, `munmap`, `mremap`,
     `madvise`, `brk`, `rt_sigaction`, `rt_sigprocmask`, `rt_sigreturn`, `sigaltstack`, `futex`, `sched_yield`,
     `getrandom`, `clock_gettime`, `getpid`, `gettid`, `exit`, `exit_group`; for a provider also `memfd_create` and
     `ftruncate`; and `tgkill` only to the process itself. The list was written from what the standard library,
     glibc and Wasmtime call on these paths, and the run shows it is enough; it was not pruned by tracing the calls
     that succeed, so some entries (`readv`, `statx`, `newfstatat`, `lseek`, `sched_yield`, `mremap`, perhaps
     others) may go unused. Every other call fails with `EPERM`: among them `open`,
     `openat`, `socket`, `connect`, `kill`, `pidfd_send_signal`, `clone`, `clone3`, `fork`, `execve`,
     `io_uring_setup`, `ptrace`, `shmget`, `bpf`. The three holes the development run's note listed for its deny
     list, x32 numbers, `io_uring_setup` and `pidfd_send_signal`, are each closed by the allow-list.

**A provider's file-size limit.** Wasmtime writes each module's initial linear memory into a `memfd` it maps
copy-on-write, and `RLIMIT_FSIZE` bounds a `memfd` like any file: at 0, that write failed with `EFBIG` on the runner
and no provider started (Actions run 42357330795). A provider's `RLIMIT_FSIZE` on Linux is therefore 16 MiB, the
binding's bound on a part's linear memory; with an empty read-only root, a `memfd` is the only file it can write.
The compiler's stays 0.

**Killing a provider's process.** The platform's process id is `unshare`'s. SIGKILL to `unshare` alone reached the
module's process only through its parent-death signal, after that process had already answered the next operation
(Actions run 42357946086, `a_killed_provider_process_is_started_again_and_the_others_keep_answering`). Killing, and
dropping, a provider's process now sends SIGKILL to the module's process first, as `/proc/<pid>/task/<pid>/children`
lists `unshare`'s child, then to `unshare`, and reaps it.

The runner setting the isolation needs is in [Target and machine](#target-and-machine).

## The isolation probes

`the_compiler_and_every_provider_process_reach_no_network_no_home_file_no_other_process_and_inherit_nothing`
(`tests/admission.rs`) starts each child as the platform starts it, under its own limits, with `--probe <file>
<socket> <pid>`, while the platform holds a file of `$HOME` (`/home/runner/.profile` in the strace below) open on a descriptor with
close-on-exec cleared and listens on a Unix-domain socket. The child confines itself, then tries each thing and
reports. Both reports, as `probes.log` gives them:

| Probe | `rutent-wasm-compiler` | `rutent-wasm-provider` |
|---|---|---|
| Read the file in `$HOME` | refused | refused |
| Signal 0 to another process: the platform's own pid | refused | refused |
| TCP connect to `127.0.0.1:9` | refused | refused |
| Connect to the platform's Unix-domain socket | refused | refused |
| Create a file in its working directory | refused | refused |
| Start a process (`/bin/sh -c true`) | refused | refused |
| Descriptors above the standard three, the inherited one among them | none open | none open |
| Landlock ABI applied | 8 | 8 |

Which layer refused first: a diagnostic `strace -f -e status=failed` of the tests after the first, failing run
(Actions run 42357330795, a development run, the jail as here) shows each probe's attempt failing in seccomp with `EPERM`: `socket` for
both connects, `openat` for the read, the write and `/bin/sh`'s `/dev/null`, `kill` for the signal. The other layers
stand behind it and were not probed one at a time: with seccomp off, the file named would not exist in the empty
root, Landlock would refuse any open, the new network namespace has only a loopback that is down, and the PID
namespace has no process of that number.

## Gaps found

- **The role suite through the binding** (`B-01`): not run.
- **Limits beyond CPU and linear memory** (`B-14`, `G-05`): none per module or provider for outbound calls, state or
  pending work, and nothing bounds a provider process's whole memory.
- **Output schema** (`B-19`): patterns and lengths aren't checked.
- **Spectre** (`G-09`): defaults, not a choice.
- **Fuzzing** (`B-09`) and **a second machine** (`B-11`, `G-04`): not run.
- **The runner setting**: the isolation needs unprivileged user namespaces with full capabilities inside them, which
  Ubuntu 24.04 restricts by default; the run sets `kernel.apparmor_restrict_unprivileged_userns=0` for itself.
- **The allow-list unpruned**: written from reading, not from a trace of the calls the children make; it may hold
  entries they never use.
- **Layers probed together**: the probes test the jail as a whole; seccomp refuses each attempt first, and the
  file-system view, Landlock and the namespaces behind it were not each probed alone.
- **Two processes per provider**: the platform holds `unshare`'s id; the module runs in its one child. Measurements of
  a provider's memory read the child.
- **The refusal for a guest stopped mid-operation** is `PlatformRefusal::Unavailable`, and **re-admitting a version**
  is refused as `UnreadableBinary`: the suite's enums have no closer reason.
- **Signing** and **routes** are the suite's placeholders, as in the development run.
