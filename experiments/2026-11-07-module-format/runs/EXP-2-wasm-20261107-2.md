## Gaps found

`-1`'s gaps stand, but for the per-call bound, which is closed in the binding. Added or narrowed:

- **The admitting compiler has no wall-time deadline.** It has 60 CPU seconds and 8 GiB of address space, and the
  platform reads it without a deadline. It is the platform's own program, but it parses hostile input.
- **One kind case the contract doesn't cover.** When the forwarded kind is declared but the guest names another,
  the binding refuses the call as `undeclared_kind`, as pvm-binding does. `validate_call_against` reads no refusal
  reason for that case.
- **The suite's kind probe** can't see M4 (above).
- **The fuel figures are calibrated off the platform.** The test tells the two budgets apart for any cost per
  request between about 6.7 and 200 million units. The stand-ins measured about 14 million (`c`) and 33 to 40
  million (`rs`) on the development Mac, built there by the same rustc and by Homebrew's clang. The run doesn't
  print how many of the thirty finished on the runner.
- **The macOS evidence** for M5 is from the development machine only.
- **Two CPU models, one machine code, not scored.** This run ran on an AMD EPYC 9V74. Its push run,
  [42368299910](https://github.com/bloque-app/rutent/actions/runs/42368299910), ran the same commit on an EPYC 7763.
  Both compiled all 16 parts to the same machine code, by every SHA-256 in their reports. That is what `B-11` asks.
  But the push run is a development run with no id or note of its own, so `B-11` and `G-04` stay not run. Scoring
  them would mean giving that run an id and a note, as `EXP-2-pvm-20261107-2` was given one.
- **pvm-binding has the same per-call bound**, left unchanged: its worker sets `GAS_PER_CALL` on each outside
  request (`rutent-pvm-worker.rs:212`), and its platform reads the worker (`binding.rs:1051`) and the admitting
  compiler (`binding.rs:405`) with no deadline. Its `B-03` and `B-13` weren't run; its note now says they would be
  bounded per call, and per-operation bounds are `F-013`'s.
