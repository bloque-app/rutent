## What it ran

The command, from the workflow's step in the `pvm` job, with `RUN_ID` the label `EXP-2-pvm-ci-7` the workflow gave a push run, and `REPORTS` the directory it uploaded:

```
experiments/2026-11-07-module-format/pvm-binding/run.sh "$RUN_ID" --digests "$REPORTS/digests.txt"
```

The workflow's two jobs, as for `-1`:

- **`pvm`:** built the binding and the 16 stand-in parts (four categories, two languages, a sandboxed and an outside part
  each) with the toolchains above; ran the isolation test (`tests/isolation.rs`), the binding's tests (6 unit
  tests, the `dirs` stub's 1, and `tests/boundary_suite.rs`' 4, which took 61.9 s), and then the module-boundary
  suite once per category, `rs` and `c` each time, with `run_id` `EXP-2-pvm-ci-7` and an output limit of 4096.
- **`pvm-rederive`:** on a second runner (the same image, kernel and CPU model), took the `pvm` job's 16 blobs, compiled each part
  with the same engine settings, and compared the machine-code digests with the first runner's: "every part's
  machine code is the same on both runners". It also compiled each part twice in two admitting-compiler processes.

Results, from `run.log`:

- All four categories' reports passed: `format` `polkavm`, `languages` `["rs", "c"]`, `output_limit` 4096, no
  findings, nothing uncovered, `missing_languages` 0, 82 of 82 exercised, `passed()` true. `M-01` to `M-16` pass in
  both languages. 64 workers started per category, 62 alive at the end, 62 distinct process ids, 152 PolkaVM sandbox
  worker processes, no load refused for a digest, no host call refused before a record, and no child wrote to its
  standard error. Each failed upgrade (`upgrading-rs 1.2.0`, `upgrading-c 1.2.0`) trapped in `start`.
- The admission checks were as expected in both languages: a sandboxed part importing `rt_secret`, one importing an
  undeclared `clock_now`, a truncated blob, bytes that aren't a program, and the outside part offered as the
  sandboxed part were each refused as `UnreadableBinary`, and the honest stand-in was admitted afterwards.
- The isolation probes were refused as in `-1` (the worker: no such file, no such process, network unreachable,
  read-only file system; the admitting compiler: not permitted); the System V probe was allowed in the worker's own
  IPC namespace and refused in the admitting compiler.
- Medians over each category's 76 admissions and loads: compile of both parts in the admitting compiler 335 to
  343 µs; the admission round trip, process start included, 5.25 to 5.41 ms; a load into a worker 204.5 to 204.7 ms.
  These are on an EPYC 9V74 and aren't the figures `B-06` cites; `B-06` is `-1`'s, on the EPYC 7763 that the Wasm
  binding's scored run also had.
