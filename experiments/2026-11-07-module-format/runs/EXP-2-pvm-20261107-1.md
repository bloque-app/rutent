binding's programs an AppArmor profile that allows user namespaces (`G-16`).

## What changed on Linux

Each fix is its own commit on `exp2/pvm-linux`, after the workflow (`fd2e1de`, renamed in `fb48326`):

- **`f2359c1`:** `unshare` is found on the platform's `PATH`, since the child's environment is cleared.
- **`0a0e373`:** clang 18 doesn't know the `nonstring` attribute, so the C slot uses it only where clang does. The
  C stand-ins build with Ubuntu's clang.
- **The worker's capability drop (`6c49191`, after a diagnosis on the runner in `29621ff`, `d66bebf` and `7083313`).**
  - Dropping every capability left PolkaVM's sandbox unable to start its guest process (an initialization
    timeout), and so did keeping only `CAP_SETUID` and `CAP_SETGID`. Every other step of the worker's confinement
    left the sandbox working.
  - Without a drop, the worker could unmount what hides `/home`.
  - The worker now enters a further user and mount namespace, which locks every mount it made, then drops
    `CAP_SYS_ADMIN`. The sandbox works, and unmounting `/home`, `/tmp` or `/run` is refused.
  - The temporary diagnosis was removed in `6c49191`. `29621ff` also added the `sandbox` and `umount` probes, which stay.
- **`8c77e89`:** the suite test says why it fails: releases that didn't start, refusals, children's standard error.
- **`554de34`:** a `pvm-rederive` job, and `--digests` and `--digests-only` in the suite runner, for `B-11`.

The admitting compiler's empty root, resource limits and `seccomp` allow-list, and the worker's hidden directories,
read-only mounts, `/proc` left writable and resource limits, all worked as first written.

## Gaps this run records

- `G-13`: upstream says not to use it in production.
- An operator obligation: Ubuntu 24.04's AppArmor restriction on unprivileged user namespaces must be lifted, or
  the binding's programs given a profile that allows them.
- The worker keeps every capability but `CAP_SYS_ADMIN` in its own user namespace, because PolkaVM's sandbox
  needs some of them. Which ones wasn't narrowed further. Its mounts are locked, and it has no network.
- `B-01`, `B-14` and `B-19` fail (above).
- `B-08`: the probes test the confinement as a whole, so its layers were not each probed alone; the admitting
  compiler drops no capabilities and has no Landlock.
- `B-11` and `G-19` rest on two AMD CPU models only.
- Not run: `B-03` to `B-05`, `B-09` in full, `B-13`, `B-15` to `B-18`, `G-20`, `G-21`, `G-24` to `G-26`.
