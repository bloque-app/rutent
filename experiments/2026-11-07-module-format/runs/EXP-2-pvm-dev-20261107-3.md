## What changed from `-2`

### macOS isolation

- **The profile** now ends with `(deny process-info*)(deny iokit-get-properties)`. These two denials matter:
  - Without them, `(deny default)` still let a child list every process on the machine, read another process's
    path and task information, and read the IOKit serial number. A scratch program checked this under the same
    profile.
  - Both programs start and work with the denials.
- **The profile's allowances:** the program, the root directory, the system's library and `dyld` paths, the two
  page-size `sysctl`s and signals to itself, as `-2` established.
- **Inherited descriptors.** A profile never mediates a read of a descriptor a process already holds: the scratch
  program read an inherited descriptor on a file in the user's home directory. So every child now closes its
  descriptors from 3 up before it execs (`isolation::close_inherited`).
  - On macOS it lists its own descriptors with `PROC_PIDLISTFDS` (before any profile applies). On Linux it uses
    `close_range`. Otherwise, or if those fail, it closes every descriptor below its open-file soft limit, at most
    2^20.
  - This also closes the standard library's pipe for reporting a failed `exec`, so such a failure shows only as the
    child exiting.
- **Standard error.** Each child's standard error is a pipe of its own. The platform keeps the first 64 KiB of
  each, labelled by provider and worker or by admission, and none of it reaches the platform's own stream. In this
  run no child wrote any.

The probes in `tests/isolation.rs`, which `run.sh` runs, and the suite runner's own table:

| Probe | Worker | Admitting compiler | Without the isolation |
|---|---|---|---|
| Control: the program runs in its isolation | allowed | allowed | allowed |
| Read a file in the user's home directory | refused | refused | allowed |
| Read a descriptor the platform holds on such a file, open across `exec` | refused | refused | allowed (the test checks it) |
| `SIGTERM` to another of the user's processes, still running afterwards | refused | refused | allowed |
| Another process's path (`proc_pidpath`) | refused | refused | allowed |
| The IOKit serial number (`IOPlatformSerialNumber`) | refused | refused | allowed |
| A TCP connection to `127.0.0.1` | refused | refused | allowed |
| A connection to a listening Unix socket in the temporary directory | refused | refused | allowed (the test checks it) |
| Create a file in the temporary directory | refused | refused | allowed |
| Create a file at `/` | refused | refused | refused: macOS's system volume is read-only |
| Standard error is the child's own pipe | yes | yes | not applicable |
| An `IPC_PRIVATE` System V shared-memory segment | **allowed** | **allowed** | allowed |

"Without the isolation" for the read and the signal was checked by hand in `-2`. For the descriptor and the Unix
socket, the test checks it each run, running the same program with no profile; the rest were checked by hand.

**System V IPC.** `shmget`, `semget` and `msgget` with `IPC_PRIVATE` succeed under the profile. Neither
`(deny ipc-sysv*)`, nor `(deny ipc-sysv-shm)(deny ipc-sysv-sem)(deny ipc-sysv-msg)`, nor `(deny ipc*)` refused them
in a scratch program. An `IPC_PRIVATE` object has no key, so another process can reach it only by its id, which
the creator would have to pass on through a channel the profile refuses. It stays open, recorded as a gap. On
Linux, each process's new IPC namespace keeps such objects its own.

B-08 is `pass (binding)`, macOS only.

### The Linux path, written but not run

- **The worker:**
  - also hides `/run` and `/var/run`;
  - keeps `/proc` writable while every other mount is read-only, for PolkaVM's sandbox child, which writes its own
    `/proc/self/{setgroups,gid_map,uid_map}`;
  - drops all its capabilities after confining itself: effective, permitted, inheritable and ambient. So it can't
    unmount what hides those directories. It keeps the bounding set, which the processes PolkaVM starts in user
    namespaces of their own need.
- **Process ids.** `Worker::pid` reports the worker's own process id, read from `/proc/<unshare>/task/<unshare>/children`
  or, without that, by its parent in `/proc/*/stat`, not `unshare`'s.
- **A new probe.** `tests/isolation.rs` connects to a socket it binds under `$XDG_RUNTIME_DIR`, normally in `/run`,
  and expects a refusal.
- **Verification.** The code type-checks and passes `clippy -D warnings` for `x86_64-unknown-linux-gnu`, and has
  never run. Its first run is the scored run's `run.sh`, which may need fixes there.

### The release kept apart until accepted

- **A waiting release** keeps its binaries apart from the running release's until its acceptance. Before, admitting
  a widening release of a version already running replaced the running version's binaries. The next restart then
  brought back the widening release under the running release's declaration, or failed and left the provider
  `Unavailable`.
- **A version names one release.** A release of a version already admitted or waiting is refused, as
  `UnreadableBinary`, with its reason recorded.
- **The test.** `a_waiting_release_leaves_the_running_one_in_force_through_a_restart_and_a_version_names_one_release`
  passed in both languages:
  - re-admitting the running 1.0.0, widened, is refused;
  - a widening 1.1.0 waits;
  - a restart gives a new process, running 1.0.0, which answers as `{provider}-1.0.0`.

### The digest gate and the refusal counts

- **The digest gate.** A load also carries each blob's SHA-256 as admission received it (`artefact.received`). The
  worker compares it before parsing, then compares its compilation's digest with the admitted one, and refuses
  before instantiating. A refusal is its own message, which the platform counts as a digest mismatch (0 in this
  run).
- **Outside requests.** Each refused outside request is counted in "host calls refused before a record", with its
  reason. The reasons are: not the contract's shape, another transaction, an undeclared operation, or another
  request already in flight. This run counted 0: the suite's modules make none.
